Cross-Row Consistency Guide

Confirm header, unit, format, and source context before comparing multiple rows.

The same shape can carry different meanings

A number, a short label, or an icon can look identical across rows and still mean different things. Two rows are only comparable when their header, unit, format, and source context all line up. Comparing before that confirmation produces a number, not a comparison.

Step 1 — Confirm the header

Make sure the two cells sit under the same column header. A value pulled from different headers is not the same kind of value, even when it reads the same.

Step 2 — Confirm the unit

Check that the unit is the same. A measurement, a weight, a count, or a size can share a numeric shape while using different units.

Step 3 — Confirm the format

Check that the format matches. A value written one way in one row and another way in the next may not mean the same thing at all.

Step 4 — Confirm the source context

Check that both rows come from the same kind of source and position. Different sources can use the same shape for different options.

Field ruleA number, label, or icon is not portable. It carries the unit, option, and context of its own row, and must be re-confirmed before any cross-row comparison.
iMargin definition: comparing two rows with different units is two readings, not one comparison.

A worked comparison

  1. Header: confirmed the same for both rows.
  2. Unit: confirmed equal before any reading.
  3. Format: confirmed matching across both rows.
  4. Source context: confirmed before comparing.
